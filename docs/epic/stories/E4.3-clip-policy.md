# E4.3 — Clip contribution policy and the content boundary

**Epic:** E4 · Open-source readiness · **Depends on:** E2.4, E4.2 · **Size:** S
**Plan:** `docs/superpowers/plans/2026-10-08-looped-loader-oss-readiness.md` → Task 7
**Spec:** §9 (accepted risk)

## Goal

Write down the rule that keeps the project from drowning in its own content, and make the
tooling enforce it for everything added from now on. The 32 existing clips are an accepted,
recorded risk; a *new* clip arriving in a pull request must not be.

## Scope (checklist)

- [ ] `CONTRIBUTING.md` section **"Adding a clip"**: accepted licences (CC0, public domain,
      CC-BY with attribution, or the contributor's own work), the required provenance
      fields, an explicit "no third-party memes or re-uploads", the review requirement, and
      the takedown route.
- [ ] The pipeline refuses a clip with no provenance (E2.4), and the assets verification
      fails on a published set that contains one — so the rule is enforced where the clip
      enters, not in a comment.
- [ ] `docs/content-policy.md`: why the existing 32 are marked `unverified`, what the
      grandfathering list is, what a clean default set would require (E4.5), and the
      project's position stated plainly — this repository redistributes third-party clips
      with the risk accepted by its owner, and that is a fact about the project, not a
      footnote.
- [ ] `NOTICE` gains the contribution clause and the takedown procedure with a stated
      response expectation.
- [ ] The policy is linked from `README.md`, `CONTRIBUTING.md` and `NOTICE`.

## Acceptance criteria

- A pull request that adds a clip without provenance fails
  `pnpm --filter @topclans/looped-loader-assets test` — proved once with a fixture clip
  added to a scratch copy of the assets directory, then removed.
- A clip whose id is not in `provenance-exceptions.json` and whose licence is `unverified`
  fails the pipeline; a clip with a real licence and a source URL passes.
- `docs/content-policy.md` is reachable from all three files above, verified by following
  the links rather than by trusting the edit.

## Out of scope

- Automated licence detection. Nothing in this repository can tell whether a contributor's
  claim is true, and pretending otherwise would be worse than the honest review step.
- Removing the existing clips. That is E4.5 and it is owner-gated.

## Risks

- **The policy cannot detect a lie.** The honest limit is to require a source URL so the
  claim is checkable, and to say in `CONTRIBUTING.md` that the reviewer checks it. This
  limitation is stated in `docs/content-policy.md` rather than hidden.
- A strict policy discourages contributions of clips, which is the main thing a user might
  want to contribute. Accepted: the alternative is a repository that cannot be defended.
