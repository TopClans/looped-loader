# E4.1 — Repo hygiene and package metadata

**Epic:** E4 · Open-source readiness · **Depends on:** E1.1 · **Size:** M
**Plan:** `docs/superpowers/plans/2026-10-08-looped-loader-oss-readiness.md` → Task 1
**Spec:** §4.10 (build and tooling)

## Goal

A contributor's first pull request should be about their change, not about formatting, and
the npm package page should look like a real project rather than a tarball with a name.
Both are cheap, and both are the difference between "someone can contribute" and "someone
closes the tab".

## Scope (checklist)

- [ ] `.editorconfig`, Prettier config, and an ESLint flat config covering TypeScript and
      Vue SFCs. Scripts: `pnpm lint`, `pnpm lint:fix`. CI runs `lint`.
      Keep the rule set small and justified — no rule that Prettier already owns.
- [ ] Commit style: Conventional Commits, enforced by `commitlint` **in CI only**. No
      husky: a pre-commit hook that rejects a contributor's first commit is a worse
      experience than a red check they can read.
- [ ] `.nvmrc` naming the development version (22), matching `engines` and the CI matrix.
- [ ] Metadata in all three published `package.json` files: `repository` (with
      `directory`), `homepage`, `bugs`, `keywords`, `author`, `engines`.
      `repository.url` must match the GitHub URL **case-sensitively** — trusted publishing
      and provenance both depend on it, and npm's own troubleshooting notes that a mismatch
      surfaces only at publish time as a misleading `ENEEDAUTH`.
- [ ] `scripts/check-manifests.mjs`: asserts the required fields exist in each published
      package, that `repository.url` matches the expected case-sensitive string, and that
      `private` is absent or false. Runs in CI and in `pnpm -r test`.

## Acceptance criteria

- `pnpm lint` green on the whole workspace, including the demo and the tools.
- `node scripts/check-manifests.mjs` green, and **fails** when `repository` is removed from
  one package — proved once, then restored.
- A commit with a non-conventional subject fails the `commitlint` job in CI.
- All three package.json files carry the same `repository.url` string, verified by the
  script rather than by eye.

## Out of scope

- Renovate, semantic-release, and any release automation beyond what E5.1 does.
- Editor-specific config beyond `.editorconfig` and Prettier (no `.vscode` shipping
  opinions to contributors).

## Risks

- ESLint plus Vue plus TypeScript is a configuration surface that can consume a day and
  produce nothing. Timebox it: if a rule cannot be justified in one line, it does not go in.
- `commitlint` in CI will reject the repository's own historical commit subjects if it is
  ever pointed at history. It checks the PR's commits only.
