# E3.5 — CI matrix and coverage thresholds

**Epic:** E3 · Quality evidence · **Depends on:** E1.1 · **Size:** M
**Plan:** `docs/superpowers/plans/2026-10-08-looped-loader-oss-readiness.md` → Task 3
**Spec:** §7 (testing), §8 (acceptance criteria 1)

## Goal

The supported platform matrix is real rather than declared, and coverage cannot collapse
quietly. A library that claims Node `>=20.11` and runs only on Ubuntu/Node 22 has not
tested that claim — and the transcode tool shells out to ffmpeg on Windows paths, which is
exactly where an untested claim breaks.

## Scope (checklist)

- [ ] Matrix: `ubuntu-latest` and `windows-latest` × Node 20, 22, 24. ffmpeg installed per
      OS (`apt-get install -y ffmpeg` / `choco install ffmpeg -y`), with the install step
      asserting `ffmpeg -version` succeeds rather than assuming it.
- [ ] Jobs: `lint`, `typecheck`, `build`, `test` (matrix), `assets-verify` (the no-ffmpeg
      manifest check, so the committed media is verified even when the matrix is red).
- [ ] Coverage: vitest thresholds per package (statements, branches, lines), set just below
      the value measured on the commit that introduces this story, and raised only in a
      commit that says it is raising them.
- [ ] The Windows leg must actually run the ffmpeg-guarded integration tests. The job
      asserts the reported test count is non-zero and that nothing was skipped, because a
      matrix leg that silently skips the integration tests is worse than no leg.
- [ ] `timeout-minutes` on every job; a `concurrency` group that cancels superseded runs;
      pnpm store caching keyed on `pnpm-lock.yaml`, and explicitly **no** cache in the
      release workflow.
- [ ] `pnpm install --frozen-lockfile` everywhere, so an uncommitted lockfile fails loudly.

## Acceptance criteria

- All six matrix legs green on a pull request.
- The Windows leg's log shows the transcode integration tests ran (non-zero count, no
  `skipped`).
- Lowering a coverage threshold is not possible without editing the config, and a
  deliberately uncovered branch fails the run — proved once by adding a branch and
  reverting it.
- A run triggered twice in quick succession cancels the first — visible in the Actions log.

## Out of scope

- macOS in the matrix. Nothing in this project is macOS-specific and the runner cost buys
  no signal; noted here so the omission is a decision rather than an oversight.
- Third-party coverage services. A threshold in the config is enough for one maintainer,
  and it keeps the pipeline free of external tokens.

## Risks

- The Windows leg is the slowest and the most likely to flake on ffmpeg installation.
  Mitigation: assert the ffmpeg version in the install step, so a flake reports itself as
  an install failure rather than as a mysterious test failure.
- Six legs multiply CI minutes. If it becomes expensive, drop Node 20 first (it is the
  oldest supported, and `engines` documents the floor) and record the decision.
