# E4.5 — *(optional)* Freely-licensed default clip set

**Epic:** E4 · Open-source readiness · **Depends on:** E2.4, E4.3 · **Size:** L
**Plan:** `docs/superpowers/plans/2026-10-08-looped-loader-oss-readiness.md` → Task 11 (optional)
**Spec:** §9 (accepted risk)

**Owner-gated, and it may be declined.** This story exists so the option is real and costed,
not to argue for it. The owner accepted the copyright risk on the current 32 clips
(spec §9, quoted verbatim there), and that decision stands until they revisit it.

## Goal

If the owner ever wants a set that is cleanly redistributable — for a company policy, a
sponsor, a store listing, or simply to stop worrying — the work is already planned and the
project can switch without breaking a single consumer.

## Scope (checklist)

- [ ] Source 8–12 clips whose licences permit redistribution, with the licence and the
      source URL recorded per clip: Wikimedia Commons (CC0/PD), Pexels, Pixabay, Mixkit.
      Verify each licence at the source page and record the URL, not the search result.
- [ ] Run them through the same pipeline and the same QC gate — no exceptions, no manual
      files. If a free clip cannot pass the seam metric, it does not ship.
- [ ] Publish as `@topclans/looped-loader-assets` with a per-clip `provenance.license` and
      `sourceUrl`, and no `unverified` entries.
- [ ] Keep the current set available as a documented alternative: either a second package
      or a `--set <name>` flag in the pipeline plus a documented manifest swap, so a
      consumer who wants the original clips is not cut off.
- [ ] Update `README.md` to state which set is which, and `docs/content-policy.md` to
      record the change.

## Acceptance criteria

- Every clip in the new default set has a licence and a source URL in the manifest, and the
  assets verification passes with the grandfathering list empty.
- The QC report shows the same thresholds as the current set: SSIM ≥ 0.93, seam regression
  ≤ 10 %, within the 250 KB budget, whole set ≤ 5 MB.
- A consumer who pins the old assets package version keeps working — proved by installing
  the previous version in a scratch directory and rendering a clip.
- `README.md` names both sets and says plainly why two exist.

## Out of scope

- Removing the current set from the registry. npm cannot unpublish an old version, so the
  honest options are deprecation and a documented replacement — decided at the time, not
  here.
- Any legal review. This story makes the licences *recorded and checkable*; it does not
  provide legal advice.

## Risks

- **Finding genuinely well-looped free clips is slow.** The current set was hand-picked for
  the loop quality, and a free set may be visibly worse. Budget for it honestly: this could
  take longer than the whole build phase, for a set that is less funny.
- **Licence drift.** A source page can change its licence after the fact. Mitigation: record
  the URL *and* the retrieval date, and keep the downloaded original in the assets
  pipeline's inputs so the claim can be re-checked.
- The two-set outcome doubles the assets a maintainer must keep passing QC. If the free set
  ships, the original becomes a frozen archive with no further updates — stated here so it
  is a decision rather than a surprise.
