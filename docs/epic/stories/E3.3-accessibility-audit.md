# E3.3 — Accessibility audit with axe and `ACCESSIBILITY.md`

**Epic:** E3 · Quality evidence · **Depends on:** E1.6 · **Size:** S
**Plan:** `docs/superpowers/plans/2026-10-08-looped-loader-oss-readiness.md` → Task 5
**Spec:** §4.6 (behaviour), §4.7 (accessibility)

## Goal

The accessibility claims stop being assertions in a spec and become measurements with an
artifact. A loader is invisible to a sighted user for two seconds and is the *only* thing a
screen-reader user hears during those two seconds, so this is not a checkbox.

## Scope (checklist)

- [ ] Run axe-core inside the browser pass (E3.1's harness, not jsdom) against the demo's
      contact sheet and scenario board. Threshold: zero `serious` and zero `critical`
      violations; `moderate`/`minor` are listed with a decision each.
- [ ] Component-specific checks that axe cannot infer:
      - the root carries `role="status"` and `aria-live="polite"` while pending;
      - the `<video>` is `aria-hidden="true"` and never enters the accessibility tree;
      - the label text is reachable by the accessibility tree (a visually-hidden element,
        not `display: none`);
      - the loader never takes focus and contains no focusable element;
      - under `prefers-reduced-motion: reduce` no `<video>` element exists at all.
- [ ] Contrast is documented as a consumer responsibility, not silently assumed: the
      spinner uses `currentColor` and the overlay background is a custom property, so the
      consumer owns the pair. `ACCESSIBILITY.md` states the minimum (3:1 for the spinner
      against the overlay) and shows how to set both.
- [ ] `ACCESSIBILITY.md`: what is guaranteed, what the consumer owns, how each guarantee
      is verified, and the known limits (no captions because no clip carries audio or
      information; the clip is decoration, and the label carries the meaning).
- [ ] The axe report is committed under `docs/verification/` next to the screenshots.

## Acceptance criteria

- The axe run reports zero serious/critical violations, with the report committed.
- Removing `aria-live` from the component makes the check fail — proved once, then
  restored. A check that cannot fail is decoration.
- `ACCESSIBILITY.md` links the committed report and names the exact command that produced
  it.
- The vitest cases from E1.5 still pass unchanged; this story adds measurement, it does
  not replace the unit-level assertions.

## Out of scope

- A WCAG conformance statement. This is a component, not a site; the statement would be a
  claim about someone else's page.
- Automated a11y checks in jsdom — they give false confidence and miss the computed
  styles and the accessibility tree, which is where this component's risks live.

## Risks

- axe passes a component that is still unusable with a screen reader. Mitigation: the
  accessibility-tree check above is manual and is recorded in the report as manual, with
  what was observed.
- The overlay mode can cover a page while a live region announces "Loading" — correct for
  the loader, potentially confusing for a page that also announces. Documented as a
  consumer note rather than solved here.
