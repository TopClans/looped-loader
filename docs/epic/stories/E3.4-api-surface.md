# E3.4 — Public API surface lock and type-level tests

**Epic:** E3 · Quality evidence · **Depends on:** E1.3, E1.4 · **Size:** M
**Plan:** `docs/superpowers/plans/2026-10-08-looped-loader-oss-readiness.md` → Task 4
**Spec:** §4.4 (core API), §4.5 (Vue adapter)

## Goal

A breaking change to the public API cannot ship unnoticed. For a library whose entire value
is a stable, tiny surface, "we changed a parameter name" is a major version, and the only
reliable way to catch it is a test that fails when the surface moves.

## Scope (checklist)

- [ ] **Exports snapshot.** A committed list of every exported name from
      `@topclans/looped-loader-core` and `@topclans/looped-loader-vue`, asserted by a test.
      Adding or removing a name fails until the same commit updates the list, which is
      exactly the moment a human should think about SemVer.
- [ ] **Type assertions** with `expectTypeOf` for the documented signatures:
      `createLoopedLoader(options): LoopedLoader`, `parseManifest(unknown): Manifest`,
      `resolveSrc(base, src): string`, `buildPool(manifest, options?): Clip[]`,
      `pickClip(pool, seed?): Clip`, and the Vue component's props and emits.
      Assertions must use concrete shapes — `expectTypeOf` against `any` passes vacuously.
- [ ] **Declarations exist.** A test asserting `dist/index.d.ts` is present and non-empty
      for both published packages after a build. This catches the failure mode where
      `vue-tsc` emits nothing and the package ships without types while every other check
      stays green.
- [ ] **README sync.** A test that every prop declared in `LoopedLoader.vue` appears in the
      README props table, and vice versa. Implementation is a regex over the `defineProps`
      block compared with the table's first column — deliberately simple. If it proves
      noisy in practice, drop it and record why in the tracker rather than weakening it
      into something that always passes.
- [ ] **Error-code lock.** The six `ErrorCode` values are asserted as a set, so adding a
      seventh is a deliberate act that also touches the spec.

## Acceptance criteria

- `pnpm -r test` green.
- Deleting one export from `packages/core/src/index.ts` fails the snapshot test — proved
  once, then restored.
- Renaming a prop in the component fails the README sync test — proved once, then restored.
- `expectTypeOf` assertions fail when a parameter's type is widened (checked once by hand
  with a scratch edit, not committed).

## Out of scope

- API Extractor or any generated `.api.md` report. The snapshot plus the type assertions
  cover the risk for a surface this small, at a fraction of the toolchain cost.
- Compatibility testing against older Vue 3 minors beyond the declared peer range.

## Risks

- Type tests are easy to write vacuously. The mitigation is in the acceptance criteria:
  each assertion is checked once against a deliberate break.
- The README sync test couples documentation to implementation. That coupling is the
  point, but it can be annoying; the fallback is documented above instead of a silent
  loosening.
