# E4.4 — Public repository settings, branch protection, security features

**Epic:** E4 · Open-source readiness · **Depends on:** E4.2 · **Size:** S
**Plan:** `docs/superpowers/plans/2026-10-08-looped-loader-oss-readiness.md` → Task 8
**Spec:** §9 (accepted risk), §10 (preconditions)

**Owner-gated and irreversible.** The repository becomes public here, which publishes 32
third-party clips. The owner has accepted that risk in writing (spec §9); this story is
where the acceptance turns into an action, and it happens once.

## Goal

The repository looks and behaves like a maintained project, and the switch to public is a
deliberate, checked step rather than a checkbox someone clicks.

## Scope (checklist)

- [ ] Description, homepage URL, topics (`vue`, `loader`, `spinner`, `video`, `webm`,
      `mp4`, `looping`, `typescript`), and a social preview image.
- [ ] Branch protection on `main`: require a pull request, require the status checks from
      E3.5, require linear history, disallow force-pushes and deletions, require
      conversation resolution.
- [ ] Tag protection for `v*`, so a release tag cannot be moved.
- [ ] Enable Dependabot alerts and security updates, secret scanning with push protection,
      and CodeQL default setup for JavaScript/TypeScript.
- [ ] Labels: `good first issue`, `help wanted`, `bug`, `documentation`, `assets`,
      `release`.
- [ ] Flip `visibility` to public — **only** after the owner has reviewed the contact sheet
      (E3.1) and confirmed in the current conversation.
- [ ] Immediately after the flip, re-run the two checks that are cheap now and expensive
      later: `git log --all -- gifs/` is empty, and no file in history contains a
      credential-shaped string.

## Acceptance criteria

- `gh api repos/TopClans/looped-loader/branches/main/protection` shows the required checks
  and the linear-history rule.
- `gh api repos/TopClans/looped-loader` shows `visibility: public`, the topics, and the
  homepage.
- Secret scanning and push protection report `enabled`; Dependabot alerts report `enabled`;
  CodeQL has at least one completed analysis.
- A direct push to `main` is rejected by the protection rule — proved once, on purpose,
  from a scratch clone.

## Out of scope

- GitHub Actions environments with manual approval for releases. E5.1 uses the trusted
  publisher's own staging option instead, which is the stronger control.
- Making the assets package's content "clean". That is E4.5 and it may never happen.

## Risks

- **The flip is irreversible in practice.** Clips become public, and a later removal leaves
  them in forks and caches. The only real mitigation is the owner's review beforehand,
  which is why it is a precondition rather than a step.
- Push protection can block a legitimate push if a test fixture looks like a token. Know
  the bypass path and never use it silently: if it fires, the fixture changes, not the
  protection.
- CodeQL on a small TypeScript library mostly restates what ESLint and the type checker
  already catch. It is enabled because its absence is a question a security-conscious
  consumer asks, not because it will find much.
